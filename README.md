# WP Multilang Press

WordPress-плагин мультиязычности, построенный по модели TranslatePress:

```
1 запись WordPress  +  N языковых URL  +  переводы строк в своих таблицах
```

Дубли постов не создаются. Плагин перехватывает уже отрисованный HTML, разбирает его в DOM, подставляет переводы из базы и отдаёт готовую страницу на `/en/...`. Поэтому переводится всё, что реально вывела тема: тексты, меню, шапка, подвал, виджеты, формы, подписи к картинкам — а не только содержимое записи.

Текущее состояние — **Этапы 1, 2 и часть Этапа 3**. Перевод по-прежнему вводится вручную — но теперь можно попросить ИИ (OpenAI) предложить перевод одной кнопкой, проверить его и сохранить самому. Никакой автоматики: плагин не переводит сайт целиком сам и не ходит в OpenAI в фоне.

## Что умеет сейчас

- Языки сайта: код, URL-слаг, статус `опубликован` / `черновик`, язык по умолчанию.
- Языковые адреса: `/about/` — русский, `/en/about/` — английский. Язык определяется только по URL, без cookie.
- Один канонический 301: лишний префикс языка по умолчанию и неверный регистр слага. Черновой язык отдаёт 404.
- Серверный перевод готового HTML: текстовые узлы, `alt`, `title`, `placeholder`, `aria-label`, надписи кнопок, `<title>` и meta description.
- Автоматический сбор строк: страницы, открытые на дополнительном языке, пополняют словарь.
- **Визуальный редактор**: предпросмотр страницы рядом с панелью перевода, выбор текста кликом, сохранение без перезагрузки.
- **Translation blocks**: абзац, разорванный тегами `<b>` и `<a>`, переводится целиком вместе с разметкой.
- Админка «Перевод строк»: фильтры по языку и статусу, поиск, ручной ввод перевода.
- Удаление переводов: по одной строке и все переводы выбранного языка сразу.
- Переключатель языков: один пункт в меню WordPress (выпадающий список или в ряд, с emoji-флагами), шорткод `[mlp_language_switcher]` и виджет.
- Ключ OpenAI хранится в базе данных, вводится в админке — доступ к файлам хостинга не нужен.
- На дополнительном языке в списках показываются только переведённые записи.
- Мультиязычная карта сайта со взаимными `hreflang` для поисковиков.
- Базовое SEO: self-canonical, взаимный hreflang с `x-default`, атрибут `lang`.
- **Перевод с ИИ**: кнопка рядом с полем перевода — и в списке строк, и в визуальном редакторе — заполняет поле подсказкой от OpenAI. Ничего не сохраняется автоматически: перевод нужно проверить и нажать «Сохранить» самому. Дневной лимит символов защищает от случайных расходов.

Чего пока нет: автоматической фоновой очереди перевода, обхода всего сайта одной кнопкой (pretranslate), glossary и translation memory, истории правок с откатом, замены картинок и ссылок для конкретного языка, перевода slug, sitemap-адаптеров, поддержки WooCommerce, gettext и динамического JS-контента.

## Требования

| Компонент | Версия |
|---|---|
| PHP | 8.1+ (рекомендуется **8.4+**) |
| WordPress | 6.4+ |
| MySQL / MariaDB | MySQL 8 / MariaDB 10.6+ |
| Постоянные ссылки | любая структура, кроме «Простые» |

На PHP 8.4+ используется встроенный HTML5-парсер `\Dom\HTMLDocument` — быстрый и корректный. На 8.1–8.3 плагин переключается на libxml `DOMDocument`: он тоже работает, но на нестандартной разметке точность ниже.

**Зависимостей в рантайме нет.** Папку `vendor/` заливать на хостинг не нужно: если автозагрузчика Composer нет, плагин подключает собственный PSR-4 загрузчик.

## Установка

1. Скопируйте папку плагина в `wp-content/plugins/wp-mlp` (имя папки может быть любым).
2. Активируйте «WP Multilang Press» в разделе «Плагины». При активации создаются четыре таблицы и настройки по умолчанию: русский как основной язык, английский на `/en/`.
3. Откройте «Настройки → Постоянные ссылки» и нажмите «Сохранить» — это пересоберёт языковые правила адресов.

Если структура постоянных ссылок стоит «Простые», плагин покажет предупреждение: языковые URL при ней не работают.

## Как пользоваться

### Добавить язык

«Мультиязычность → Языки»: заполните код (`de`), URL-слаг (`de`), название (`Deutsch`), при желании emoji-флаг (`🇩🇪`) и статус. Сохраните — правила адресов пересоберутся сами.

- **Опубликован** — язык доступен посетителям и попадает в `hreflang`.
- **Черновик** — язык виден только в админке: его URL отдаёт 404, в `hreflang` его нет. Удобно, пока перевод не готов.

Язык по умолчанию отдаётся без префикса и черновиком быть не может.

Флаг — необязательное поле, плагин не подставляет его сам: код языка не всегда однозначно связан со страной (у английского нет «своего» флага), поэтому выбор оставлен за вами. Флаг появится перед названием в переключателе языков.

### Перевести страницу в визуальном редакторе

Самый быстрый способ, когда нужно перевести конкретную страницу.

1. «Мультиязычность → Визуальный редактор». Либо откройте нужную страницу на сайте и нажмите «Перевести страницу» в верхней панели.
2. Выберите язык и при необходимости укажите путь страницы, например `/about/`.
3. В предпросмотре справа наведите курсор — переводимые места подсветятся рамкой. Нажмите на нужное.
4. Слева появятся оригинал и поле перевода. Впишите текст, нажмите «Сохранить» (или Ctrl+Enter) — текст в предпросмотре заменится сразу.
5. Переходите по ссылкам прямо в предпросмотре: режим редактора сохраняется.

Кнопка «Удалить перевод» очищает перевод только этой строки.

### Перевести абзац целиком

Иногда абзац разорван тегами: `Читайте <b>наш</b> блог` — это три отдельных куска, и перевести их по отдельности грамотно нельзя, потому что порядок слов в языках разный.

Нажмите на такой абзац в редакторе — под полем перевода появится кнопка «Перевести абзац целиком». После нажатия абзац становится одной строкой, и переводить его нужно вместе с разметкой: `Read <b>our</b> blog`.

Разрешены только оформительские теги (`b`, `i`, `a`, `span`, `img`, `br` и подобные). Скрипты, стили и обработчики событий вырезаются.

### Перевести строку списком

1. Откройте любую страницу сайта на дополнительном языке, например `https://site.ru/en/about/`. Плагин запомнит все найденные на ней строки.
2. Зайдите в «Мультиязычность → Перевод строк», выберите язык и при желании фильтр «Нет перевода».
3. Впишите перевод и нажмите «Сохранить» (или Ctrl+Enter).
4. Обновите страницу на дополнительном языке — текст заменится.

Строки появляются в списке **только после посещения страницы** на дополнительном языке: плагин переводит то, что реально вывела тема, и заранее знать этот список не может.

Одинаковый текст переводится один раз на весь сайт. Текст и значение атрибута считаются разными строками: «Купить» в кнопке и «Купить» в `alt` картинки переводятся отдельно.

### Удалить переводы

- Ссылка «Удалить» в строке таблицы или кнопка в редакторе — убирает один перевод.
- Кнопка «Удалить все переводы языка» под фильтрами — убирает все переводы выбранного языка. Действие необратимо и спрашивает подтверждение. Исходные строки при этом остаются, удаляются только переводы.

### Переключатель языков

Три способа поставить его на сайт.

**В меню сайта (обычно то, что нужно).** «Внешний вид → Меню» → блок «Языки» слева → отметьте **одну** из двух галочек — «Выпадающий список» или «В ряд» — и нажмите «Добавить в меню». Больше ничего делать не нужно: под этим одним пунктом плагин сам подставляет реальные языки при каждом показе меню, ничего заранее вкладывать друг в друга не требуется.

```
«Выпадающий список» → пункты появляются по наведению/клику,
                       оформлением подменю вашей темы:

Главная  Блог  Контакты  Язык ▾
                          ├ 🇷🇺 Русский
                          └ 🇬🇧 English

«В ряд» → языки видны сразу, отдельными пунктами подряд:

Главная  Блог  🇷🇺 Русский  🇬🇧 English
```

Оба пункта можно добавить одновременно и оба можно переименовать/удалить как обычный пункт меню. У пункта «Выпадающий список» название («Язык») — то, что видно как заголовок; у пункта «В ряд» название значения не имеет, он сам становится первым языком.

**Шорткод** в контенте или шаблоне:

```
[mlp_language_switcher]
[mlp_language_switcher type="dropdown"]
[mlp_language_switcher show_current="no"]
```

**Виджет** «Переключатель языков» в «Внешний вид → Виджеты».

Черновые языки не показываются нигде: доступного адреса у них нет. Если единственный опубликованный язык — сам пункт меню, переключаться не на что, и плагин его не выводит вовсе.

Выпадающий список рассчитан на темы со стандартной разметкой подменю WordPress (`.sub-menu`, класс `menu-item-has-children`) — так работает подавляющее большинство тем. Для очень нестандартных мега-меню тема может не подхватить это автоматически; в таком случае свой класс на пункт-триггер можно добавить фильтром `mlp_nav_menu_dropdown_classes`.

### Карта сайта

Плагин отдаёт собственную карту по адресу `/wp-mlp-sitemap.xml`. В ней все языковые версии со взаимными `xhtml:link hreflang` — по ним Google понимает, что `/about/` и `/en/about/` это одна страница на двух языках, а не два дубля.

Непереведённые страницы в карту не попадают: их адрес на `/en/` отдаёт русский текст, и для поисковика это был бы дубль.

Адрес автоматически добавляется в `robots.txt`, так что поисковики найдут карту сами. Отправить её вручную в Google Search Console — быстрее. Ссылка есть в «Мультиязычность → Языки».

Карта не встраивается в sitemap ядра WordPress и не подменяет карты Yoast или Rank Math — она работает рядом с ними. Причина: рендерер карты сайта в ядре выводит только `loc` и `lastmod` и молча выбрасывает `xhtml:link`, то есть языковые версии туда просто не добавить.

### Непереведённые записи

По умолчанию включено: на дополнительном языке блог, рубрики, метки и поиск показывают только записи, у которых есть хотя бы один перевод. Отключается в «Мультиязычность → Языки».

Отдельная запись при этом остаётся доступной по прямой ссылке — посетитель мог прийти из поисковика, и 404 вместо частично переведённой страницы был бы хуже.

Запись попадает в список только после того, как вы хотя бы раз откроете её на дополнительном языке: до этого плагин не знает, какие строки ей принадлежат.

## Подключение OpenAI (перевод с ИИ)

Без этого шага плагин работает как обычно — просто кнопки «Перевести с ИИ» не будет видно ни в списке строк, ни в редакторе. Доступ к файлам хостинга не нужен — всё через админку.

1. «Мультиязычность → Языки». В блоке «Ключ OpenAI» впишите ключ — <https://platform.openai.com/api-keys>.
2. Ниже — «Модель OpenAI»: точный идентификатор модели, сверьте с личным кабинетом или документацией OpenAI. «Адрес API» трогайте только для своего прокси/совместимого шлюза, по умолчанию `api.openai.com`.
3. Сохраните. В том же блоке появится «Ключ сохранён, заканчивается на «…»» — сам ключ повторно нигде не показывается, поле для ввода нового значения всегда пустое. Чтобы заменить ключ — впишите новый; чтобы оставить как есть — просто не трогайте поле при сохранении других настроек; чтобы удалить — отметьте «Удалить сохранённый ключ».
4. Задайте дневной лимит символов (по умолчанию 100 000) — это защита от случайных расходов, а не автоматизация: плагин не переводит ничего сам, лимит просто ограничивает сумму, которую можно потратить, нажимая кнопку.

Ключ хранится в базе данных сайта (опция `mlp_settings`) и никогда не выводится в HTML, JS, REST-ответы и логи (ТЗ, раздел 13) — только последние 4 символа для подтверждения «это тот ключ, что вводили». Это удобнее `.env`, но у такого хранения другой профиль риска: ключ окажется в дампе БД и в бэкапах сайта, если они не зашифрованы, — при переносе сайта или экспорте БД третьим лицам учитывайте это.

`.env` остаётся резервным способом для тех, кто предпочитает хранить ключ вне базы: `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` в `.env.example`. Приоритет всегда у поля в админке — `.env` используется, только если оно пустое.

**Как это работает:** рядом с полем перевода (в списке строк и в визуальном редакторе) появляется кнопка «Перевести с ИИ». Нажатие отправляет исходный текст в OpenAI и подставляет ответ в поле — **не сохраняя его**. Перевод остаётся черновиком (статус «Машинный»), пока вы не проверите его и не нажмёте «Сохранить» сами.

Своего провайдера (другой сервис вместо OpenAI) можно подключить фильтром, без правки ядра плагина:

```php
add_filter( 'mlp_translation_provider', function () {
    return new My\CustomProvider();
} );
```

Класс должен реализовать `WpMlp\Translation\ProviderInterface`.

## Устройство

```
wp-mlp.php                  bootstrap: заголовок плагина, автозагрузчик, запуск
uninstall.php               удаление данных — только по явной галочке
src/
  Plugin.php                композиционный корень: контейнер и хуки
  Container.php             минимальный DI
  Support/                  языковые коды, хеши, нормализация текста
  Settings/                 языки сайта в одной опции wp_options
  Routing/                  язык из URL, rewrite-правила, канонический 301
  Rendering/                output buffering, DOM, извлечение, подстановка,
                            режим редактора и маркеры узлов
  Storage/                  схема БД, репозитории, объектный кэш, дневной бюджет
  Translation/              ProviderInterface, ManualProvider, OpenAiProvider
  Admin/                    «Языки», «Перевод строк», «Визуальный редактор»
  Rest/                     эндпоинты переводов и блоков
  Frontend/                 переключатель языков, hreflang и canonical
docs/technical-spec.md      полное техническое задание
PROMPTS.md                  задания по этапам
```

### Таблицы

| Таблица | Назначение |
|---|---|
| `{prefix}mlp_sources` | исходные строки: текст, хеши, вид, язык |
| `{prefix}mlp_translations` | переводы: текст, статус, автор, провайдер |
| `{prefix}mlp_occurrences` | где встретилась строка |
| `{prefix}mlp_routes` | локализованные slug (заполняется на Этапе 4) |

Уникальность строки обеспечивает колонка `uniq_hash` — SHA-256 от всех частей ключа. Составной уникальный индекс из ТЗ 6.1 содержит nullable-колонки, а MySQL считает `NULL` значения различными, поэтому дубли он бы не остановил.

### REST API

Всем эндпоинтам нужны права `manage_options` и REST-nonce.

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/wp-json/mlp/v1/sources/{id}` | строка и её переводы на все языки |
| `PUT` | `/wp-json/mlp/v1/translations/{id}/{locale}` | сохранить перевод |
| `DELETE` | `/wp-json/mlp/v1/translations/{id}/{locale}` | удалить перевод |
| `POST` | `/wp-json/mlp/v1/translations/{id}/{locale}/suggest` | получить перевод от ИИ, не сохраняя |
| `POST` | `/wp-json/mlp/v1/blocks` | объединить абзац в translation block |
| `DELETE` | `/wp-json/mlp/v1/blocks/{id}` | разобрать блок обратно на части |

### Производительность

На прогретом словаре страница добавляет **2–3 SQL-запроса**, независимо от количества строк на ней: переводы забираются одним `IN`-запросом. Запись новых строк отложена на `shutdown`, то есть уже после отправки ответа. Отметка «строка ещё жива» обновляется не чаще раза в час на страницу.

Список translation blocks лежит в автозагружаемой опции, поэтому пока блоков нет, они не стоят ни одного запроса. Как только блоки появятся, разбор страницы начнёт дополнительно сериализовать и проверять каждый абзац с инлайновыми тегами — заметно это станет только на очень больших страницах.

Предпросмотр редактора работает иначе обычной страницы: он не кэшируется, отдаёт `noindex` и пишет найденные строки сразу, а не на `shutdown`, — иначе маркерам не на что было бы ссылаться.

Если на сайте есть постоянный объектный кэш (Redis, Memcached), переводы кэшируются между запросами; при сохранении перевода кэш обесценивается целиком через номер версии.

## Разработка

Рантайм-зависимостей нет, Composer нужен только для тестов.

```bash
composer install
composer test          # или vendor/bin/phpunit
```

Composer не обязателен — тесты запускаются и phar-архивом PHPUnit:

```bash
curl -sSLO https://phar.phpunit.de/phpunit-12.phar
php phpunit-12.phar
```

Тесты (`tests/`) проверяют чистую логику без загрузки WordPress: нормализацию строк, хеши, валидацию языковых кодов, разбор URL, сборку rewrite-правил, извлечение строк из DOM, подстановку перевода (включая запасной libxml-парсер), маркеры редактора, translation blocks, разбор `.env` и сборку/разбор запроса к OpenAI. Функции WordPress подменены заглушками в `tests/stubs.php`. Сетевой вызов к OpenAI не тестируется — `OpenAiRequestBuilder` (сборка payload, разбор ответа) специально вынесен из `OpenAiProvider` (сам HTTP-запрос), чтобы логику можно было проверить без мока сети.

Всё, что зависит от `$wpdb` и хуков, проверяется вручную на реальном сайте — сценарий приёмки описан в `PROMPTS.md`, раздел 9.

Если PHP локально не установлен:

