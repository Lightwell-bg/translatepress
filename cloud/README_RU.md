# LingoCanvas Cloud (backend)

Backend платного провайдера перевода «LingoCanvas Cloud» для WordPress-плагина LingoCanvas. Сайт присылает исходные тексты, backend переводит их ИИ-моделью (DeepSeek) и списывает символы с предоплаченной квоты аккаунта клиента.

Папка `cloud/` лежит в репозитории плагина только для удобства и **никогда не входит в ZIP плагина**.

Статус: **MVP этапа 3, не развёрнут.** Оплата через Stripe и интеграция с плагином — следующие этапы. English version: [README.md](README.md). Быстрый старт: [docs/QUICK_START.md](docs/QUICK_START.md).

## Стек

- Python 3.12, FastAPI, uvicorn
- SQLAlchemy 2 (async) + asyncpg, миграции Alembic
- PostgreSQL 16 (встроенный `pgserver` для локальной разработки и тестов)
- httpx для API DeepSeek, pytest + pytest-asyncio для тестов

## Как работают квоты

- У аккаунта есть **корзины квоты**: *месячная* на каждый оплаченный период (не переносится) и необязательные *пакеты* дополнительных символов.
- Символы списываются **сначала из месячной корзины, потом из пакетов** (пакеты — по самому раннему сроку действия). **Пакеты тратятся только пока идёт оплаченный период**: если месячная корзина истекла, неиспользованные пакеты ждут продления.
- Единица тарификации: кодовые точки Unicode **уникальных** исходных текстов запроса (одинаковые тексты отправляются и оплачиваются один раз).
- Запрос сначала **резервирует** символы, затем вызывает провайдера, затем **закрывает расчёт**: списываются только символы тех текстов, которые реально вернулись переведёнными, остальное возвращается в корзину. Запрос без достаточной квоты получает 402 и до провайдера не доходит.
- **Повтор** (тот же `request_id` и то же тело) бесплатен (`billed_chars: 0`, `replay: true`) и ограничен `max_replays`. Текст переводится моделью заново (ничего не хранится), поэтому повтор учитывается в тех же лимитах, что и новый запрос: частота на сайт и число одновременных запросов на аккаунт. Неудавшийся запрос можно повторить с тем же `request_id`: списано будет не более одного раза (`max_attempts`). Списание происходит только за завершённые (committed) попытки.
- У каждого резерва есть срок жизни (`reservation_ttl_seconds`). Фоновый **sweeper** освобождает резервы, оставшиеся после сбоя, поэтому клиента за них не списывают. Каждая попытка имеет номер (fencing-токен) и закрывает только свой резерв; единый общий дедлайн (`call_deadline_seconds`, не менее чем на 30 с меньше TTL) ограничивает все вызовы модели в запросе. Если резерв попытки освободили раньше, чем она закончилась, результат не выдаётся: `504 provider_timeout` (повторить с тем же `request_id`), а не бесплатная доставка.
- Глоссарий передаётся модели как данные в сообщении пользователя (никогда в системном промпте) и ограничен: `glossary_max_chars` и не более 2 x символов текстов + 200 (иначе 413).
- Дневной бюджет провайдера проверяется перед каждым вызовом: потрачено + двойная стоимость запроса в худшем случае; сбои с неизвестным расходом, которые могли быть оплачены (таймаут, 5xx, отмена), записываются по худшему случаю.
- Каждое изменение квоты сначала берёт **блокировку строки аккаунта** (`app/quota.py`): параллельные запросы не могут потратить одни и те же символы; CHECK-ограничения БД — последняя линия защиты. Каждое движение записывается в журнал `ledger` (только добавление).
- Тексты клиентов и переводы не хранятся и не логируются; в БД лежат только размеры, счётчики, токены и стоимость.

## Оплата (Stripe)

Этап 4, **только локально и в тестовом режиме** (ничего не развёрнуто, боевых ключей нет). Пошаговая настройка тестового аккаунта Stripe: [docs/STRIPE_SETUP.md](docs/STRIPE_SETUP.md).

- **Общий аккаунт Stripe.** Аккаунт Stripe общий с другим продуктом. Каждый создаваемый нами объект несёт метаданные `lc_app=lingocanvas` (сессия оплаты, подписка, платёж); ключи `user_id` и `product` мы не пишем никогда. Событие вебхука обрабатывается, только если у его объекта есть эти метаданные или он уже есть в наших таблицах (`subscriptions`, `payments`); всё остальное подтверждается (`200 ignored`) без единого вызова API Stripe и без изменения наших данных.
- **Регистрация без токена в ссылке.** Плагин генерирует случайный *секрет заявки* и отправляет в `POST /v1/billing/signup` только его SHA-256; клиент платит в Stripe Checkout; затем плагин опрашивает `POST /v1/billing/claim` с секретом и один раз получает токен сайта. Заявка блокируется после `claim_max_failed_attempts` неверных секретов.
- **Вебхук** `POST /v1/stripe/webhook`: подпись проверяется через `STRIPE_WEBHOOK_SECRET` (допуск 5 минут), тестовые и боевые события разделяются `STRIPE_LIVEMODE`. Строка `stripe_events` пишется в одной транзакции с последствиями: повтор ничего не меняет, а сбой даёт HTTP 500, и Stripe повторит доставку. Состояние подписки всегда берётся из живого объекта Stripe, а не из тела события, поэтому события не по порядку не вернут старое состояние.
- **Деньги в квоту.** `invoice.paid` (причины `subscription_create`/`subscription_cycle`) начисляет одну месячную корзину на период счёта (строка счёта выбирается по известной цене тарифа, строка перерасчёта никогда); пакет (разовый платёж, 12 месяцев) начисляется, когда сессия оплачена (`checkout.session.completed` с `payment_status=paid` или `async_payment_succeeded`). Квоту даёт только реальная оплата: счёт на 0 EUR или платёж не в EUR ничего не начисляет. Начисления привязаны к id счёта / платёжного намерения. Заявка регистрации становится доступной для получения токена только после того, как первый оплаченный счёт начислил квоту (не при создании подписки). Возвраты накопительные и забирают неиспользованную часть пропорционально; часть, занятая выполняющимся запросом, забирается, когда запрос её освободит. Спор ставит на аккаунт блокировку (`403 account_suspended` для перевода, получения токена по заявке и привязки сайта) и забирает неиспользованные символы; выигранный спор снимает блокировку (забранные символы сами не возвращаются); `accounts.status` (выключатель администратора) споры не меняют. Возвраты и споры, пришедшие раньше своего платежа (и по платежам другого продукта), сохраняются как id и суммы без других данных, применяются, когда платёж появится, и удаляются через `unmatched_retention_days` (90) дней.
- **Одна открытая оплата Starter.** `POST /v1/billing/checkout` с `starter` возвращает ту же ссылку, пока прежняя сессия аккаунта открыта (23 ч), поэтому двойной щелчок не создаст две подписки.
- **Больше сайтов.** `POST /v1/sites/pair-code` (токен сайта) выдаёт одноразовый код; новый сайт отправляет его в `POST /v1/sites/pair`. Лимит `max_sites` тарифа действует и для заявок, и для привязки.
- Пока не заданы оба значения `STRIPE_SECRET_KEY` и `STRIPE_WEBHOOK_SECRET`, оплата отвечает `503 billing_disabled`. Константы (адреса, сроки, лимиты) лежат в `config.ini`, раздел `[billing]`. Stripe SDK `stripe==16.0.0`, версия API зафиксирована в `app/billing/stripe_gateway.py` (`API_VERSION`).
- Проверка администратором: `python -m app.cli billing-status --account 1`.

## API

Кратко: `POST /v1/translate`, `GET /v1/account`, `GET /health`; оплата: `POST /v1/billing/signup`, `/claim`, `/checkout`, `/portal`, `POST /v1/sites/pair-code`, `/pair`, `POST /v1/stripe/webhook`. Аутентификация: `Authorization: Bearer lcc_...` (один токен на подключённый сайт). Полное описание с примерами и кодами ошибок: [docs/API.md](docs/API.md) (на английском).

## CLI администратора

```bash
python -m app.cli create-account --name "Acme" --email a@example.com --plan starter
python -m app.cli add-site --account 1 --name shop.example.com   # токен сайта печатается ОДИН раз
python -m app.cli list-sites --account 1
python -m app.cli revoke-site --site 1
python -m app.cli grant-month --account 1 [--start 2026-10-01]   # месячная квота тарифа, идемпотентно
python -m app.cli grant-pack --account 1 --pack pack_250k --ref pay_123   # --ref делает команду идемпотентной
python -m app.cli revoke-bucket --bucket 1       # забирает неиспользованные символы (возврат денег)
python -m app.cli usage --account 1 --days 30    # списания клиента (запросы/символы) и работа провайдера (вызовы, токены, стоимость)
python -m app.cli spend --days 7                 # расход на провайдера по дням
python -m app.cli sweep                          # освободить просроченные резервы сейчас
python -m app.cli billing-status --account 1      # подписка, платежи (возвращено/забрано), корзины; без секретов
```

`add-site` учитывает максимальное число сайтов тарифа. Тарифы, пакеты и лимиты лежат в `config.ini`.

## Внешние сервисы

| Сервис | Зачем | Где взять ключ | Куда вставить |
|---|---|---|---|
| DeepSeek | ИИ-модель, которая переводит (`deepseek-flash`, режим thinking выключен) | <https://platform.deepseek.com> → «API keys» ([документация](https://api-docs.deepseek.com)) | `DEEPSEEK_API_KEY` в `.env` и `PROVIDER=deepseek` |
| Stripe (пока только ТЕСТОВЫЙ режим) | подписки и пакеты | <https://dashboard.stripe.com/test/apikeys> ([документация](https://docs.stripe.com)); по шагам: [docs/STRIPE_SETUP.md](docs/STRIPE_SETUP.md) | переменные `STRIPE_*` в `.env` (таблица ниже) |

Платный вызов DeepSeek без явного разрешения владельца не выполнять; для разработки держите `PROVIDER=mock`.

## Переменные окружения (`.env`)

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DATABASE_URL` | да | адрес PostgreSQL для asyncpg, `postgresql+asyncpg://user:password@host:port/dbname` (локально его печатает `scripts/local_pg.py start`) |
| `PROVIDER` | нет (`mock`) | `mock` = фальшивые переводы, без платных вызовов; `deepseek` = настоящий провайдер |
| `DEEPSEEK_API_KEY` | только при `PROVIDER=deepseek` | ключ API DeepSeek |
| `TOKEN_PEPPER` | да | секрет для хеширования токенов сайтов, не короче 32 случайных символов; при смене все выданные токены перестают работать. Создать: `python -c "import secrets;print(secrets.token_urlsafe(48))"` |
| `DAILY_SPEND_LIMIT_USD` | нет (`5`) | аварийный выключатель: когда сегодняшний (UTC) расход на провайдера достигает значения, сервис отвечает 503 `service_budget_exhausted` |
| `POSTGRES_PASSWORD` | только для docker-compose | пароль контейнера PostgreSQL; compose собирает из него `DATABASE_URL` для сервисов. Создать: `python -c "import secrets;print(secrets.token_hex(24))"` |
| `STRIPE_SECRET_KEY` | для оплаты | секретный ключ API Stripe `sk_test_...` (тестовый режим). Пусто = оплата выключена (503 `billing_disabled`) |
| `STRIPE_WEBHOOK_SECRET` | для оплаты | ключ подписи `whsec_...` точки приёма вебхуков. Пусто = оплата выключена |
| `STRIPE_PRICE_STARTER` | для оплаты | id `price_...` месячной цены Starter |
| `STRIPE_PRICE_PACK_250K` | для оплаты | id `price_...` разовой цены пакета 250 тыс. символов |
| `STRIPE_PORTAL_CONFIGURATION` | для портала | id `bpc_...` настройки Customer Portal, сделанной только для LingoCanvas; пусто = `POST /v1/billing/portal` отвечает `503 portal_not_configured` (возврата к настройке аккаунта по умолчанию, которой пользуется другой продукт, нет) |
| `STRIPE_LIVEMODE` | нет (`false`) | `false` обрабатывает только тестовые события, `true` только боевые |

`CONFIG_INI` (необязательно, нет в `.env.example`) переопределяет путь к `config.ini`. `.env` и `.env.example` должны оставаться структурно одинаковыми (те же переменные в том же порядке, различаются только значения).
