# Настройка Stripe для LingoCanvas Cloud (ТЕСТОВЫЙ режим)

Этот документ описывает, как подготовить Stripe для проверки оплаты **на вашем компьютере, на тестовых деньгах**. Реальные деньги и боевые ключи здесь не используются. Подключение боевого режима: раздел в конце, только после отдельного согласования.

## Важное до начала

- **Аккаунт Stripe общий с другим продуктом (Vira).** Поэтому: ничего не меняйте в уже существующих товарах, ценах, точках приёма вебхуков и в настройках Customer Portal «по умолчанию». Мы только **добавляем** своё: два товара, одну отдельную настройку портала и одну точку приёма вебхуков.
- Работаем только в **тестовом режиме**. Тестовый режим Stripe полностью отделён от боевого: тестовые товары, ключи и платежи не видны в боевом режиме и наоборот. В новых аккаунтах тестовый режим может называться «Sandbox» (песочница): это то же самое для наших целей.
- **Покупателей (Customer) создаёт только сервер**, всегда с пометкой (metadata) `lc_app=lingocanvas`. По этой единственной пометке продукт Vira узнаёт события LingoCanvas: метаданные в Stripe НЕ переходят от покупателя к оплате, подписке, счёту, платежу и спору, зато все они ссылаются на покупателя. **Никогда не создавайте покупателей LingoCanvas вручную в Dashboard без этой пометки.** Инвариант: каждый Customer, с которого LingoCanvas берёт деньги, несёт `lc_app=lingocanvas`. Дополнительно сервер перед каждой платёжной сессией по аккаунту (пакет, повторная подписка Starter) и перед сессией портала дописывает эту пометку покупателю (обновление metadata сохраняет остальные ключи); если Stripe недоступен, сессия не создаётся (ответ 502). Действующих боевых покупателей LingoCanvas до этого не существовало, поэтому дозаполнять (backfill) ничего не нужно. Если покупателя для LingoCanvas всё же создали вручную в Dashboard, задайте ему metadata `lc_app` = `lingocanvas`.
- Секретные ключи (`sk_test_...`, `whsec_...`) никому не отправляйте и не вставляйте в чат. Они хранятся только в файле `.env` на вашем компьютере.
- Версия API Stripe, под которую написан код: **`2026-09-30.endive`** (константа `API_VERSION` в `app/billing/stripe_gateway.py`). Её нужно выбрать в шаге 5.

## Шаг 1. Войдите в Stripe и включите тестовый режим

1. Откройте ссылку: <https://dashboard.stripe.com/login> и войдите в аккаунт (тот же, что у Vira).
2. Вверху справа найдите переключатель **«Test mode»** / **«Тестовый режим»** (ползунок рядом с названием аккаунта; в новых аккаунтах это выбор «Sandbox» в меню аккаунта слева вверху) и включите его.
3. Что должно появиться: оранжевая полоса или пометка **«Test mode»** / **«Тестовый режим»** вверху страницы, адреса страниц содержат `/test/`.
4. Если полосы нет: вы в боевом режиме. Ничего не создавайте, нажмите переключатель ещё раз.

## Шаг 2. Создайте два товара с ценами

### 2.1. Подписка Starter (9 евро в месяц)

1. Откройте <https://dashboard.stripe.com/test/products> (в адресе должно быть `/test/`).
2. Нажмите кнопку **«Add product»** / **«Добавить товар»** (вверху справа).
3. В поле **«Name»** / **«Название»** введите: `LingoCanvas Starter`.
4. В блоке **«Pricing»** / **«Цены»** выберите **«Recurring»** / **«Регулярный платёж»**.
5. В поле **«Amount»** / **«Сумма»** введите `9.00`, валюта **EUR**.
6. В списке **«Billing period»** / **«Период оплаты»** выберите **«Monthly»** / **«Ежемесячно»**.
7. Откройте **«More pricing options»** / **«Дополнительные параметры цены»**, если они свёрнуты, и в поле **«Tax behavior»** / **«Налогообложение»** выберите **«Inclusive»** / **«Включая налог»** (цена уже содержит НДС).
8. Нажмите **«Add product»** / **«Добавить товар»** (внизу или вверху справа).
9. Что должно появиться: страница товара `LingoCanvas Starter` с одной ценой «€9.00 per month».
10. Скопируйте номер цены: в блоке **«Pricing»** / **«Цены»** наведите мышь на строку цены, нажмите значок копирования рядом с **«API ID»** (начинается с `price_`). Если значка нет, нажмите на саму цену: номер `price_...` будет в адресе страницы и в блоке «Details».
11. Запишите его: это значение `STRIPE_PRICE_STARTER`.

### 2.2. Пакет 250 тысяч символов (7 евро, разовый платёж)

1. На той же странице товаров нажмите **«Add product»** / **«Добавить товар»**.
2. В поле **«Name»** / **«Название»** введите: `LingoCanvas Pack 250k`.
3. В блоке **«Pricing»** / **«Цены»** выберите **«One-off»** / **«Разовый платёж»** (на английском интерфейсе бывает «One time»).
4. В поле **«Amount»** / **«Сумма»** введите `7.00`, валюта **EUR**.
5. В поле **«Tax behavior»** / **«Налогообложение»** выберите **«Inclusive»** / **«Включая налог»**.
6. Нажмите **«Add product»** / **«Добавить товар»**.
7. Что должно появиться: страница товара с ценой «€7.00».
8. Скопируйте `price_...` так же, как в пункте 2.1. Это значение `STRIPE_PRICE_PACK_250K`.

Если интерфейс выглядит иначе: суть одна. Нужно два товара: один с **регулярной ежемесячной** ценой 9 EUR, один с **разовой** ценой 7 EUR, у обоих налог «включён в цену». Номера цен всегда начинаются с `price_`.

## Шаг 3. Скопируйте секретный ключ API

1. Откройте <https://dashboard.stripe.com/test/apikeys>.
2. Найдите строку **«Secret key»** / **«Секретный ключ»** и нажмите **«Reveal test key»** / **«Показать тестовый ключ»**.
3. Что должно появиться: ключ вида `sk_test_...` (в боевом режиме он начинался бы с `sk_live_`: такой ключ сюда **не** вставляйте).
4. Нажмите на ключ, чтобы скопировать. Это значение `STRIPE_SECRET_KEY`.
5. Если кнопки показа нет: нажмите **«Create secret key»** / **«Создать секретный ключ»**, назовите `lingocanvas-local` и скопируйте показанное значение (оно показывается один раз).

## Шаг 4. Отдельная настройка Customer Portal для LingoCanvas

Customer Portal это страница Stripe, где клиент меняет карту, смотрит счета и отменяет подписку. У Vira своя настройка портала «по умолчанию». **Мы её не трогаем.** Мы создаём отдельную настройку только для LingoCanvas, и наш сервер явно указывает её при каждом открытии портала. Без значения `STRIPE_PORTAL_CONFIGURATION` портал не открывается вообще: сервер отвечает `503 portal_not_configured` и не обращается к Stripe (запасного варианта «взять настройку по умолчанию» нет, потому что она принадлежит Vira).

1. Откройте <https://dashboard.stripe.com/test/settings/billing/portal>.
2. Что должно появиться: страница «Customer portal» / «Портал клиента». Если уже есть настройка Vira (у неё пометка **«Default»** / **«По умолчанию»**), **ничего в ней не меняйте и не нажимайте «Save»**.
3. Найдите кнопку **«New configuration»** / **«Новая конфигурация»** (вверху справа или рядом со списком «Configurations» / «Конфигурации») и нажмите её. Если такой кнопки нет, откройте меню **«⋯»** рядом с заголовком страницы и выберите **«Create configuration»** / **«Создать конфигурацию»**.
4. В поле названия (**«Name»** / **«Название»**), если оно есть, введите `LingoCanvas`.
5. Включите (ползунок вправо): **«Update payment methods»** / **«Изменение способов оплаты»**, **«View invoice history»** / **«История счетов»**, **«Cancel subscriptions»** / **«Отмена подписок»** с вариантом **«At end of billing period»** / **«В конце оплаченного периода»**.
6. **«Update subscriptions»** / **«Изменение подписок»** оставьте выключенным.
7. В списке товаров портала (если он есть) оставьте только `LingoCanvas Starter`.
8. Нажмите **«Save changes»** / **«Сохранить изменения»**.
9. Что должно появиться: в списке конфигураций появилась новая строка `LingoCanvas`. У неё **не должно** быть пометки «Default»: пометка остаётся у настройки Vira.
10. Откройте созданную конфигурацию (клик по строке). Номер вида `bpc_...` указан на странице как **«Configuration ID»** / **«ID конфигурации»** (также в адресе страницы). Скопируйте его. Это значение `STRIPE_PORTAL_CONFIGURATION`.
11. Если вы случайно изменили настройку по умолчанию: откройте её, верните прежние переключатели (если не помните, не сохраняйте ничего и сообщите об этом) и не нажимайте «Save».

## Шаг 5. Точка приёма вебхуков (понадобится, когда сервер будет в интернете)

Вебхук это письмо от Stripe нашему серверу «клиент заплатил». Адрес `https://cloud.centerai.eu/...` заработает только после развёртывания на сервере. **Пока сервер не развёрнут, этот шаг можно пропустить и использовать Stripe CLI (шаг 7).**

1. Откройте <https://dashboard.stripe.com/test/webhooks>.
2. Нажмите **«Add endpoint»** / **«Добавить конечную точку»**. В новом интерфейсе кнопка называется **«Add destination»** / **«Добавить назначение»**: тогда выберите «Your account» / «Ваш аккаунт», затем тип назначения **«Webhook endpoint»** / **«Конечная точка вебхука»**.
3. В поле **«Endpoint URL»** / **«URL конечной точки»** введите: `https://cloud.centerai.eu/v1/stripe/webhook`
4. В списке **«API version»** / **«Версия API»** выберите **`2026-09-30.endive`**. Если такой версии в списке нет, выберите самую новую и запишите, какую: код понимает старую и новую форму объектов, но сообщите об этом.
5. В выборе событий (**«Select events»** / **«Выбрать события»**) отметьте **ровно эти 12** событий (используйте поиск по названию):
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
   - `checkout.session.expired`
   - `invoice.paid`
   - `invoice.payment_failed`
   - `customer.subscription.created`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `charge.refunded`
   - `charge.dispute.created`
   - `charge.dispute.updated`
   - `charge.dispute.closed`
6. Нажмите **«Add endpoint»** / **«Добавить конечную точку»** (в новом интерфейсе **«Create destination»** / **«Создать назначение»**).
7. Что должно появиться: страница новой точки со статусом «Enabled» / «Включена».
8. На странице точки найдите **«Signing secret»** / **«Ключ подписи»** и нажмите **«Reveal»** / **«Показать»**. Скопируйте значение вида `whsec_...`. Это значение `STRIPE_WEBHOOK_SECRET` для сервера.
9. Другие точки вебхуков (Vira) не трогайте: наша работает независимо, а сервер сам игнорирует события, которые не относятся к LingoCanvas.
10. Важно про возвраты и споры. События `charge.refunded` и `charge.dispute.*` не несут наших пометок, поэтому сервер не может сразу отличить платежи LingoCanvas от платежей Vira. Если платёж ему пока неизвестен, он сохраняет только id и суммы (никаких данных клиента, без запросов к Stripe), ничего не применяет и удаляет такую запись через 90 дней (`unmatched_retention_days` в `config.ini`). Если потом появится наш платёж с тем же id, возврат или спор применится сразу. Поэтому возвраты и споры Vira не влияют на LingoCanvas, а возврат, пришедший раньше оплаты, не теряется.

## Шаг 6. Впишите значения в `.env`

1. Откройте PowerShell: клавиша Windows, наберите `PowerShell`, нажмите Enter.
2. Вставьте команду и нажмите Enter:

```powershell
cd D:\1PythonProjects\1_WORDPRESS\translatepress\cloud
notepad .env
```

3. Что должно появиться: Блокнот с файлом `.env`. В конце файла есть блок «Stripe billing» с пустыми значениями.
4. Допишите значения сразу после знака `=`, без пробелов и кавычек:
   - `STRIPE_SECRET_KEY=` вставьте `sk_test_...` (шаг 3);
   - `STRIPE_WEBHOOK_SECRET=` вставьте `whsec_...` (шаг 5 или шаг 7);
   - `STRIPE_PRICE_STARTER=` вставьте `price_...` Starter (шаг 2.1);
   - `STRIPE_PRICE_PACK_250K=` вставьте `price_...` пакета (шаг 2.2);
   - `STRIPE_PORTAL_CONFIGURATION=` вставьте `bpc_...` (шаг 4);
   - `STRIPE_LIVEMODE=false` оставьте как есть.
5. Сохраните: **Файл → Сохранить** (Ctrl+S) и закройте Блокнот. Остальные строки `.env` не меняйте.
6. Перезапустите сервер, чтобы он прочитал новые значения. В окне PowerShell, где он работает, нажмите Ctrl+C, затем:

```powershell
cd D:\1PythonProjects\1_WORDPRESS\translatepress\cloud
.venv\Scripts\Activate.ps1
uvicorn app.main:app --host 127.0.0.1 --port 8077
```

7. Что должно появиться: строка `Uvicorn running on http://127.0.0.1:8077`. Окно оставьте открытым, пока проверяете оплату.
8. Проверка, что оплата включена. Откройте **второе** окно PowerShell и вставьте:

```powershell
cd D:\1PythonProjects\1_WORDPRESS\translatepress\cloud
.venv\Scripts\Activate.ps1
python -c "import httpx;print(httpx.post('http://127.0.0.1:8077/v1/billing/claim',json={'claim_id':'x','claim_secret':'y'}).text)"
```

9. Что должно появиться: `{"error":{"code":"claim_not_found","message":"Claim not found."}}`. Это значит «оплата включена, такой заявки нет».
10. Если появилось `billing_disabled`: пустой `STRIPE_SECRET_KEY` или `STRIPE_WEBHOOK_SECRET`, либо сервер не перезапущен. Проверьте шаги 4 и 6.

## Шаг 7. Проверка через Stripe CLI (вебхуки без интернета)

Stripe CLI это программа Stripe, которая принимает события из Stripe и пересылает их на ваш компьютер. Так можно проверить вебхуки, пока сервер не развёрнут.

### 7.1. Установка

1. Откройте <https://github.com/stripe/stripe-cli/releases/latest> и скачайте файл `stripe_X.X.X_windows_x86_64.zip` (X.X.X это номер версии).
2. Распакуйте его (правая кнопка → «Извлечь всё») в папку `C:\stripe`. Внутри должен лежать `stripe.exe`.
3. Откройте PowerShell и проверьте:

```powershell
C:\stripe\stripe.exe --version
```

4. Что должно появиться: строка `stripe version X.X.X`. Если Windows пишет, что файл не найден, проверьте, что `stripe.exe` лежит прямо в `C:\stripe`, а не во вложенной папке.

### 7.2. Вход

1. В PowerShell выполните:

```powershell
C:\stripe\stripe.exe login
```

2. Нажмите Enter, когда программа предложит открыть браузер. В браузере нажмите **«Allow access»** / **«Разрешить доступ»**.
3. Что должно появиться: в PowerShell «Done! The Stripe CLI is configured…».

### 7.3. Приём событий

1. В PowerShell (это окно оставьте открытым) выполните:

```powershell
C:\stripe\stripe.exe listen --forward-to localhost:8077/v1/stripe/webhook
```

2. Что должно появиться: `Ready! You are using Stripe API Version [...]. Your webhook signing secret is whsec_...`.
3. Скопируйте этот `whsec_...` (он **отличается** от ключа точки из шага 5: он нужен только для проверок на компьютере), вставьте в `.env` как `STRIPE_WEBHOOK_SECRET=` (шаг 6) и перезапустите сервер.
4. Не закрывайте это окно: пока оно открыто, события из Stripe приходят на ваш сервер.

### 7.4. Пробные события

1. В **третьем** окне PowerShell выполните:

```powershell
C:\stripe\stripe.exe trigger invoice.paid
```

2. Что должно появиться: в окне с `stripe listen` строки `--> invoice.paid` и `<-- [200] POST http://localhost:8077/v1/stripe/webhook`. В ответе сервера `{"status":"ignored"}`.
3. Это **правильный** результат: `stripe trigger` создаёт события без наших пометок `lc_app`, и сервер обязан их проигнорировать (так он не трогает платежи Vira). Так же проверьте `customer.subscription.updated` и `charge.refunded`: все три должны быть «ignored».

### 7.5. Полная проверка оплаты (тестовой картой)

1. Окна с сервером (шаг 6) и с `stripe listen` (шаг 7.3) должны быть открыты. В новом окне PowerShell выполните (создаёт заявку на подписку; секрет придуман для теста):

```powershell
cd D:\1PythonProjects\1_WORDPRESS\translatepress\cloud
.venv\Scripts\Activate.ps1
python -c "import hashlib,httpx;s='my-local-test-secret-0123456789abcdef';r=httpx.post('http://127.0.0.1:8077/v1/billing/signup',json={'plan':'starter','site_name':'test.example.com','claim_secret_sha256':hashlib.sha256(s.encode()).hexdigest()});print(r.text)"
```

2. Что должно появиться: JSON с `claim_id` и `checkout_url`. Скопируйте `checkout_url` целиком и откройте в браузере.
3. На странице оплаты Stripe введите тестовую карту: номер `4242 4242 4242 4242`, срок любой в будущем (например `12/34`), CVC `123`, имя и почта любые. Нажмите **«Subscribe»** / **«Оформить подписку»**.
4. Что должно появиться: страница «спасибо» (она может не открыться, пока сайт `centerai.eu/lingocanvas/thanks/` не существует: это нормально). В окне `stripe listen` появятся строки `checkout.session.completed`, `invoice.paid` и др. с `[200]`.
5. Заберите токен (вместо `ВАШ_CLAIM_ID` вставьте `claim_id` из шага 2):

```powershell
python -c "import httpx;r=httpx.post('http://127.0.0.1:8077/v1/billing/claim',json={'claim_id':'ВАШ_CLAIM_ID','claim_secret':'my-local-test-secret-0123456789abcdef'});print(r.status_code, r.text)"
```

6. Что должно появиться: `200` и JSON с `token`, `site_id`, `account_id`. Токен показывается один раз; повторный запрос даст `409 already_claimed`.
7. Состояние аккаунта (вместо `1` подставьте `account_id`):

```powershell
python -m app.cli billing-status --account 1
```

8. Что должно появиться: подписка `active`, платёж `kind=subscription amount=900eur`, корзина `granted=100000`.

### 7.6. Другие тестовые случаи

Тестовые карты Stripe (любой срок в будущем, любой CVC):

| Что проверить | Номер карты |
|---|---|
| Успешный платёж | `4242 4242 4242 4242` |
| Карта сохраняется, но списание не проходит (неудачное продление) | `4000 0000 0000 0341` |
| Платёж, который клиент потом оспаривает (спор) | `4000 0000 0000 0259` |
| Требуется подтверждение 3-D Secure | `4000 0025 0000 3155` |

Возврат: <https://dashboard.stripe.com/test/payments> → откройте платёж → **«Refund»** / **«Возврат»** → полный или частичный. Через несколько секунд `python -m app.cli billing-status --account 1` покажет `refunded=...` и `revoked=...`.

Если в окне `stripe listen` вместо `[200]` стоит `[500]`: сервер не смог обработать событие, и Stripe повторит доставку сам. Посмотрите окно сервера: строка `stripe webhook failed type=... event=... error=...` назовёт класс ошибки (текст ошибки и данные клиента в журнал намеренно не попадают). Если `error=BillingError`, обычно причина в том, что `STRIPE_PRICE_STARTER` / `STRIPE_PRICE_PACK_250K` в `.env` не совпадают с ценой, по которой купили.
